# 2026-10-16

## 2026-10-16 - Rename defect: OG image still said "LinguaFix"

- `site/public/og-image.png` (1200x630 social preview, referenced by
  `site/src/layouts/Base.astro` as `og:image`/`twitter:image`) was hand-made
  before the rename, so the binary kept rendering **LinguaFix**. A text-only
  rename never touches a bitmap - found it by OCR'ing the PNG with `tesseract`.
- Fixed with a reproducible generator: `scripts/make_og_image.py` inlines
  `site/public/logo.svg` + the self-hosted Inter/JetBrains Mono woff2 that Astro
  emits (`site/dist/_astro/fonts/`), renders absolute-positioned HTML with
  headless `chromium`, and refuses to write if the old name is present.
- It needs a prior `npm run build` in `site/` (fonts are gitignored); raises
  `SiteNotBuilt` otherwise, which the test turns into a skip.
- `tests/test_og_image.py` pins size, a non-blank render, the served path, and
  (via `tesseract`, skipped when absent) that the card shows `Lingvix`.
- Measured every element's bbox against the original and matched them
  (logo blue square 90,120,240,270; title cap 279,140..209; subtitle width
  867 vs 865; card blue arrow 407..446; footer 566..598). Environment note: no
  PIL/cairo/gi here - decode/encode PNG with pure Python (`struct`+`zlib`).

## 2026-10-17 - Final rename to Klyrshift + release reconciliation (v0.2.8.3)

- **The name went through three stages, and only the last is final:**
  `LinguaFix` -> `Lingvix` -> `Klyrshift`. The GitHub repository was renamed to
  `Pavel1778/Klyrshift` (old slug 301-redirects). Keep `linguafix`/`lingvix` only
  where load-bearing: `Conflicts`/`Replaces`, `LEGACY_APP_NAMES`, `_ASSET_PREFIXES`.
- **Config-directory migration is now real.** `config.migrate_legacy_config()`
  copies `config.toml` + `snippets.toml` from `~/.config/{lingvix,linguafix}` into
  `~/.config/klyrshift` on the first `load_config()` with no explicit path. It
  *copies* (a downgrade still finds it), only when no current config exists, and
  only the default path triggers it. Any doc that said "not migrated" is stale.
- **Release assets carry three possible prefixes.** `_ASSET_PREFIXES` is
  `("klyrshift-dict-", "lingvix-dict-", "linguafix-dict-")`, newest first. The
  published `v0.2.8` release ships `linguafix-*` (and the `.deb`/tarball as
  `linguafix_*`); the next one ships `klyrshift-*`.
- **Version is 0.2.8.3** in `pyproject.toml`, `src/klyrshift/__init__.py`,
  `site/src/consts.ts`, the CHANGELOG heading, and the `.deb` examples in
  `README.md`/`docs/INSTALL.md`/`docs/TESTING.md`.
- **`release_consistency.py --latest` MUST fail until the tag is published** --
  that is the design, not a bug. `--source` is the offline half and passes now.
- **Site hosts are still `linguafix.layero.app` / `linguafix.vercel.app`.** The
  `klyrshift.*` names resolve in DNS but return 404 (no deployment). The canonical
  origin is written into canonical/og:url/hreflang/sitemap, so pointing it at a
  404 drops the page from search. `tests/test_repo_urls.py` pins the two origins.
- **Deploy is an external blocker:** `site/deploy.sh` needs an interactive
  `npx layero@latest login` (or the Vercel dashboard); no Vercel/Layero token
  exists in this environment. Builds fine, cannot publish from here.
- **Verified green:** ruff, isort, black, `mypy --strict .` (123 files), `bash -n`,
  `release_consistency.py --source`, and 1037 tests pass (72 skipped: no GTK4
  display, no `tesseract`). No tag and no GitHub Release were created -- that
  needs separate explicit permission.
