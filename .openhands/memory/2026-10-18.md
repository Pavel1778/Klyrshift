## Session 2 — screenshot determinism + security hardening (committed work)

### DEFECT fixed: nondeterministic README screenshots
`advanced-settings.png` and `dictionary.png` changed bytes on every regeneration
(`main-window.png` was stable). Root cause was TWO wall-clock animations, not one:
1. `Adw.ViewStack` cross-fade on `set_visible_child_name`.
2. The focused entry's blinking text caret.
The first fix attempt (`_settle` pumping until `transition-running` clears) was
insufficient: the `Adw.ViewSwitcher` underline keeps ticking *after* the flag
clears, and `transition-running` never covers the caret at all.
Fix in `scripts/make_screenshots.py`: disable the stack transition, pump the main
loop for a fixed `_SETTLE_SECONDS = 0.6` window, and set
`gtk-cursor-blink=False`. Verified: 4/4 runs byte-identical for all three PNGs,
and the committed PNGs now match a fresh render exactly.
Regression guard: `tests/test_screenshots.py` asserts the two flags are present,
plus a `KLYRSHIFT_RENDER_TEST=1` test that renders twice and compares bytes.
(Residual diff before the caret fix was only 2x17 px at x=213,y=164 — the caret.)

### Security: update_check.py B310 removed (not suppressed)
`fetch_latest(url=...)` fed a caller URL straight into `urlopen`, which follows
`file:`/`ftp:`. Added `_require_https()` rejecting any non-https scheme before the
socket is opened, and annotated the `urlopen` call with `# nosec B310` (scheme is
now proven). Bandit MEDIUM B310 gone; only LOW findings remain.
Tests: `test_fetch_latest_refuses_non_https` (file/ftp/http, asserts urlopen is
never reached). NOTE: the other two `urlopen` sites (`thematic.py`, `dictionary.py`)
use hardcoded constants + `# nosec B310` — no caller-controlled URL, no bug.

### site/ npm audit — NOT fixed, deferred (documented)
11 vulns (1 critical, 6 high, 3 moderate, 1 low). OSV confirms NO fix exists on
Astro 5.x: the CRITICAL (`GHSA-26w7-cxv4-gfx2`, AVIF RCE) needs astro>=7.2.8, and
`sharp` HIGHs need sharp>=0.35.5 (outside astro 5's `^0.34.0` range). Fixing means
a 5 -> 7 double-major migration (the Tailwind integration changed) — a project, not
a drive-by. The site is `output: "static"` with no `server:defer`, no `define:vars`,
no spread attrs, so most XSS advisories are unreachable; the `sharp`/AVIF RCE
matters only if a build ingests untrusted images (it does not — only repo assets).
Decision: added `.github/dependabot.yml` (pip + npm/site + github-actions, weekly)
so the bump is proposed and CI-validated rather than blind-merged.
