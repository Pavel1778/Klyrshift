## Shipped
- **v0.2.9 is published and is Latest.** Tag `v0.2.9` -> `e453bc1` (merge of PR

  `release_consistency.py --latest` prints `ok`; the

- **A real undo defect was found and fixed** (`fbcc18c`): the undo history was
  bounded by time and depth only, so it did not notice the caret had moved.
  After a fix, typing anything else then pressing the undo hotkey deleted the
  recorded char count from the *new* text and retyped the old word over it.
  `daemon._invalidate_undo_history()` now clears the history for any key that is
  neither a hotkey action nor the observed `Ctrl+Z`; a Space that triggers a new
  fix records a fresh entry. Pinned by `tests/test_undo_suppression.py`.
- `release.yml` now smoke-tests the `.deb` on **Debian 13** as well as Debian 12
  (`SMOKE_IMAGE=debian:13`), since trixie is the target (udev `71-*` before

## Traps re-confirmed
- **`python -m build` needs the venv** (`.venv/bin/python -m build --sdist`).
  The system `python` has no `build.__main__`, so the sdist silently fails and
  the workflow's `ls dist/*.tar.gz` list fills with `ls:` error words, which the
  `--assets-file` gate then rejects. Always check the sdist exists.
- **Simulate the release gate locally before tagging:**
  `release_consistency.py --source --tag vX.Y.Z --assets-file <staged>` must
  print `ok`. Build the `.deb` + sdist + dict archives first so the list is real.
- **CI does not run `--latest`**; only the tag-triggered `release.yml` does. A
  bumped-but-unreleased version is fine on `main`, and CI stays green.
- **`file_editor` corrupts non-ASCII in `CHANGELOG.md`** — the bump was done
  with `python3 - <<PYEOF` / a `/tmp/*.py` script under `encoding="utf-8"`;
  verified 0 C1 control chars and Cyrillic intact afterwards.
- **One `python3 - <<'EOF'` heredoc per terminal call** — the runtime rejects a
  call that contains both a heredoc and a second command.
