## Task

automated run breaks. Findings documented, recommendations given. No product

## What "автопрогон" is
The only automated (unattended) run that belongs to Klyrshift is the autonomous
QA engine: `klyrshift qa run` and the CI job `Autonomous QA (deterministic,
offline)`. (The NEXUS orchestrator calls one of *its* runs "Автономный прогон";
that machinery is another project — `Pavel1778/python-dispetcher` — and is out
of scope.)

## Defect found (reproducible on main, HEAD 2a296d0)
`qa/executor.build_script` joins scenario steps with `", "`, but
`simulate.run_scenario` splits the script on `","`. The commas inside a rendered
`[a, b]` list or `{k: v}` dict are indistinguishable from step separators, so a
config with **two or more** list/dict entries is shredded into bogus steps:

```
config exceptions_apps=[kitty, code], type ghbdtn, space
  split -> ['config exceptions_apps=[kitty', 'code]', 'type ghbdtn', 'space']
  -> ScenarioError: unknown key 'code]'
```

- One-element list/dict survives; two-or-more always breaks.
- `klyrshift qa run` classifies it a `harness-error` and exits `1` (CI red).
- `klyrshift simulate 'config exceptions_apps=[kitty, code], ...'` breaks too.
- Not caught: `tests/test_qa_engine.py::test_build_script_renders_lists_and_dicts`
  only asserts the *string* the builder emits, never that the simulator can run
  it. The curated corpus has exactly one non-empty config and it is a
  **single-element** list, so the default run is green by luck.

Verified fix direction (not applied): make the splitter bracket-aware (ignore
commas inside `[ ]`/`{ }`). With it, all three broken shapes run to `привет `
and `type ghbdtn, space` is unchanged.

## Secondary observation
`RunConfig.repeats` is documented but read by nothing — `runner.run` ->
`analyse` -> `reproduces(scenario)` with the hard-coded default `runs=2`.

## Same class of sharp edge
A literal comma in a `type` step is also a separator: `type hello, world` ->
`ScenarioError: unknown key 'world'`, and `type a,b` silently types `ab`.

## NEXUS task t2: extra verification of unused specifications

Task: "Ок, что уже готово?" — the follow-up: are any *declared specifications*
still unaddressed? A mechanical audit of the specification surface (every
`Config` field, GUI-bound setting, CLI option, QA knob, documented claim) for a
*reader*. An item the user can toggle that no code reads is an unused spec.

Found and fixed (product code changed this time):
- `notify_on_error` — GUI switch + help topic, but **no code read it**. Now
  `_notify_error()` fires on the daemon's failure paths (event error, buffer
  error, failed undo) with a fixed label.
- `sound_on_fix` — GUI switch, no reader. Now `_announce_fix()` plays
  `canberra-gtk-play -i bell` (gnome-session-canberra); a missing player is a
  no-op.
- `log_rotation_mb` — the «Ротация, МБ» spin was ignored; the handler was
  hard-coded to 5 MB. `setup_logging(rotation_mb=…)` now sets `maxBytes`; CLI
  foreground and the GUI both pass it; clamped to >= 1 MB.
- `RunConfig.repeats` — documented, never read (`reproduces` hard-coded 2). Now
  threaded `analyse(repeats=…) -> reproduces(runs=…)`, plus a new
  `klyrshift qa run --repeats N`.
- `title_en` (thematic) — docstring called it the authoritative English spelling
  "checked against in the test-suite", but no test did, and it had drifted from
  en.json (`gaming`/`sport`). en.json realigned to it (site already agreed).
- `hotkey_swallow` — inert by design (the daemon never issues EVIOCGRP), but its
  help text *promised* swallowing. Help text now says it is reserved and inert.

Guard: `tests/test_spec_coverage.py` — every `Config` field must have an
*attribute* read outside config.py (a GUI/help string mention does not count:
that is exactly how the dead three looked "used"); plus pins for rotation size,
sound/notify subprocess calls, and `repeats`.

`docs/SPECIFICATION_AUDIT.md` (new) records the surface, the findings and the
clearances; registered in README, PROJECT_STRUCTURE.md and build_docs.SOURCES;
handbook + CLI docs (man/completion, for `--repeats`) regenerated.

Checks: headless 1793 passed / 107 skipped, 85 %; strongest (xvfb + GUI
