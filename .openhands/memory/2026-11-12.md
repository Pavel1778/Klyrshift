## What "автопрогон" is
The only automated (unattended) run that belongs to Klyrshift is the autonomous
QA engine: `klyrshift qa run` and the CI job `Autonomous QA (deterministic,
offline)`. (The NEXUS orchestrator calls one of *its* runs "Автономный прогон";
that machinery is another project — `Pavel1778/python-dispetcher` — and is out
of scope.)

## Defect found (reproducible on main, HEAD 2a296d0)
`qa/executor.build_script` joins scenario steps with `", "`, but
`simulate.run_scenario` splits the script on `","`. The commas inside a rendered
`[a, b]` list or `{k: v}` dict are indistinguishable from step separators, so a
config with **two or more** list/dict entries is shredded into bogus steps:

```
config exceptions_apps=[kitty, code], type ghbdtn, space
  split -> ['config exceptions_apps=[kitty', 'code]', 'type ghbdtn', 'space']
  -> ScenarioError: unknown key 'code]'
```

- One-element list/dict survives; two-or-more always breaks.
- `klyrshift qa run` classifies it a `harness-error` and exits `1` (CI red).
- `klyrshift simulate 'config exceptions_apps=[kitty, code], ...'` breaks too.
- Not caught: `tests/test_qa_engine.py::test_build_script_renders_lists_and_dicts`
  only asserts the *string* the builder emits, never that the simulator can run
  it. The curated corpus has exactly one non-empty config and it is a
  **single-element** list, so the default run is green by luck.

Verified fix direction (not applied): make the splitter bracket-aware (ignore
commas inside `[ ]`/`{ }`). With it, all three broken shapes run to `привет `
and `type ghbdtn, space` is unchanged.

## Secondary observation
`RunConfig.repeats` is documented but read by nothing — `runner.run` ->
`analyse` -> `reproduces(scenario)` with the hard-coded default `runs=2`.

## Same class of sharp edge
A literal comma in a `type` step is also a separator: `type hello, world` ->
`ScenarioError: unknown key 'world'`, and `type a,b` silently types `ab`.
